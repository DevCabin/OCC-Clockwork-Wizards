# Fix Broken Images Workflow

## The Problem

Posts with images from `nerdymugs.com/wp-content/uploads/` have broken images (old WP site is down).

## The Solution

**Step 1: Mark posts with broken images**

Run this once Vercel deploy completes (~30 seconds from push):

```bash
curl -sS -X POST "https://app-liart-five-43.vercel.app/api/jobs/mark-broken-images" \
  -H "Authorization: Bearer $CRON_SECRET" \
  -d '{"dryRun": false}'
```

This marks all WP posts with broken `nerdymugs.com` images as `status: "needs_image"`.
These posts stay in the DB but won't show in the frontend.

**Step 2: Restore all other WP posts**

```bash
curl -sS -X POST "https://app-liart-five-43.vercel.app/api/jobs/restore-all-posts" \
  -H "Authorization: Bearer $CRON_SECRET" \
  -d '{"dryRun": false}'
```

This restores the remaining WP posts (those with good images or Amazon images) to `status: "ready"`.

**Step 3: Verify**

```bash
curl -sS "https://app-liart-five-43.vercel.app/api/posts/ready?limit=10" | jq '.posts[].title'
```

Should show titles of posts with working images only.

## What's Fixed

- ✅ `/api/posts/ready` now filters by:
  - Status = `ready` or `published` (not `rejected`, `needs_image`, etc.)
  - Product has non-null image_url
  - Image URL is NOT from `nerdymugs.com/wp-content` (broken)

- ✅ Frontend grid will only show posts that actually have loadable images

## Future: If you ever fix the images

Run this to restore posts marked as `needs_image`:

```bash
curl -sS -X POST "https://app-liart-five-43.vercel.app/api/jobs/restore-all-posts" \
  -H "Authorization: Bearer $CRON_SECRET" \
  -d '{"dryRun": false}'
```

(The restore route now also handles `needs_image` status.)
